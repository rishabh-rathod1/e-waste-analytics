03. Big Data Engineering Challenge

The Hierarchical Deduplication Trap

Solving multi-million-ton double counting in secondary material flow databases

04 / 10
The Problem: Parent & Child Coexistence

In raw material flow datasets, summary rows and component breakdown rows are stored in the same flat table.

Row 1: Cat1 (Refrigerator) | Layer 2 = "" | Value = 40.0 Mg [WHOLE] Row 2: Cat1 (Refrigerator) | Layer 2 = Compressor | Value = 12.0 Mg [PART] Row 3: Cat1 (Refrigerator) | Layer 2 = Foam | Value = 8.0 Mg [PART] Row 4: Cat1 (Refrigerator) | Layer 2 = Copper Coil | Value = 2.0 Mg [PART] ------------------------------------------------------------------------- Blind SUM(Value) = 40 + 12 + 8 + 2 = 62.0 Mg (55% TO 100% FALSE INFLATION!)
The PySpark Algorithmic Solution

Strict filtering isolates true Level-1 summary rows where Layer 2 is blank:

summary_df = cleaned_df.filter( col("Layer2").isNull() | (col("Layer2") == "") | (col("Layer2") == "null") ).cache()

Why Snappy Columnar Parquet?

  • Column Pruning: Queries read only requested columns from disk.
  • Predicate Pushdown: Skips whole row groups using block min/max statistics.
  • Speedup: Query latency plummeted from 90+ seconds to <1 second.
04. Distributed Processing

Dual Compute: Hadoop MapReduce vs Spark

Benchmarking low-level batch MapReduce on YARN against in-memory Spark SQL

05 / 10
Hadoop MapReduce Streaming on YARN
  • Streaming Bridge: Unix STDIN/STDOUT piping into mapper.py and reducer.py via hadoop-streaming-3.5.0.jar.
  • Parallelism: 17 Input Splits (~128MB HDFS blocks) executed across YARN containers.
  • Shuffle & Sort: YARN network partitioning groups identical nation keys for stateful reducer aggregation.
  • Execution Time: 140 seconds (map 100% reduce 100%).
# mapper.py: Emits Key \t Value if "generated" in stock_flow and layer1 != "" and layer2 == "": print(f"{location}\t{float(raw_val):.6f}")
Apache Spark 4.2.0 In-Memory Engine
  • In-Memory DAG: Eliminates intermediate disk spills by caching RDD/DataFrames directly in executor memory.
  • Catalyst Optimizer: Performs rule-based query optimization, constant folding, and physical plan generation.
  • Tungsten Engine: Generates highly optimized compact JVM bytecode for query execution.
  • ETL Speed: Full multi-table ETL across 17.5M records in 93.4 seconds.
Empirical Consistency: Both MapReduce and Spark produced identical results down to the decimal (e.g., GBR = 302,467,302.27 Mg).

Why NoSQL for Recycling Infrastructure?
  • Heterogeneous Metallurgy: Smelters, mechanical shredders, depollution stations, and hydrometallurgical extraction plants have non-uniform attributes.
  • Dynamic Categories: Nested arrays of accepted WEEE categories (["WEEE_Cat1", "WEEE_Cat4a", "WEEE_Cat5"]).
  • Geospatial Distance Queries: Instant calculation of proximity between high-waste generation hubs and authorized treatment facilities.
